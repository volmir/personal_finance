# Подготовка релиза 1.0.3 — 24.11.2026

Статус: **материалы подготовлены как черновик; небольшие правки интерфейса продолжаются, финальная release-сборка отложена по решению владельца**. Текущие скриншоты разрешено использовать повторно; новая генерация не требуется. Тег `v1.0.3` не создан. Последний опубликованный релиз — `v1.0.2 / 3`, коммит `293849bcb33355ef68df9da68e09892fe2262529`; его теги и артефакты сохраняются.

Workflow `.github/workflows/build-and-release.yml` удалён владельцем сознательно. Он не восстанавливается; автоматической подписи и публикации нет. Следующий выпуск проверяется, подписывается прежним ключом и публикуется вручную по отдельному запросу автора.

## F-Droid

`metadata/io.github.volmir.personalfinance.yml` сохраняет опубликованную `1.0.2 / 3`. Запись новой сборки добавляется после публикации и проверки подписанного APK с полным SHA окончательного релизного коммита. Ссылку `.fdroid.yml` на будущий тег нельзя считать готовой к сборке F-Droid до создания этого тега.

После публикации в основной рецепт добавляется запись, сохраняющая все прежние сборки:

```yaml
  - versionName: '1.0.3'
    versionCode: 4
    commit: <FULL_RELEASE_COMMIT_SHA>
    subdir: app
    gradle:
      - yes
```

Тогда же `CurrentVersion` / `CurrentVersionCode` основного рецепта меняются на `1.0.3 / 4`. `Binaries` и `AllowedAPKSigningKeys` сохраняются. Ожидаемое имя опубликованного APK — `PersonalFinance-v1.0.3.apk`, сертификат SHA-256 — `d67a62a233c26662269925955c653464820bf121e155ca827359c3b99d9b6609`.

Официальная контейнерная сборка и сравнение с новым подписанным APK пока не выполнены. Продолжать существующий MR `!56526`, новый MR не открывать. Состояние MR и решения мейнтейнеров в этой подготовке не запрашивались и не изменялись.

3. Собрать и подписать окончательный APK существующим релизным ключом. Переменные сборки: `KEYSTORE_PATH`, `STORE_PASSWORD`, `KEY_PASSWORD`, `KEY_ALIAS`; секреты не записывать в репозиторий и не выводить в лог.
4. Проверить подпись и точный отпечаток сертификата, пакет `io.github.volmir.personalfinance`, версию `1.0.3 / 4`, minSdk 24, targetSdk 36, отсутствие включённых `debuggable`, `testOnly` и разрешения `INTERNET`.
5. Подготовить из подписанного APK `PersonalFinance-v1.0.3.apk`, `SHA256SUMS.txt` и `SIGNING_CERTIFICATE.txt`. Контрольная сумма unsigned APK для этого не подходит.
6. Получить отдельное явное указание владельца на создание тега и публикацию. В текущей задаче они запрещены; ни один шаг публикации не выполнен.
7. После разрешения опубликовать вручную с подготовленными заметками, скачать APK и повторить проверку суммы, сертификата и установки.
8. Затем обновить основной рецепт F-Droid полным SHA и продолжить существующий MR; повторить контейнерную сборку, `fdroid lint`, сравнение через `Binaries` / `apksigcopier`.

Локальные unsigned APK, контрольные суммы и отчёты подготовки не являются подписанным релизом и не предназначены для обновления установленной версии с релизной подписью.
