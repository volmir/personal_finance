# Финансы и FIRE v2 — утверждённая функциональная и UX-спецификация

Статус: **утверждённая концепция, спецификация для реализации**. Дата: 21.11.2026.

## 1. Назначение и неизменяемые требования

Версия v2 объединяет **вариант C** (три главные вкладки) с **оптимизированным B4** (компактная закреплённая сводка симуляции). Основные вкладки: **Обзор**, **Данные**, **План**. Вторичные экраны открываются внутри выбранного пользовательского пути и не являются дополнительными вкладками.

Инварианты:

1. Существующие формулы, критерии, вычислительные результаты и доменная семантика не меняются в рамках редизайна. Изменения математической модели требуют отдельной задачи и утверждения.
2. Все существующие показатели, полное заключение, три экспорта, настройки и пользовательские данные сохраняются.
3. Изменения симуляции не записываются в исходные финансовые данные; отдельный режим FIRE всегда показывает базовую модель.
4. Сохраняются шесть локализаций, светлая/тёмная темы, доступность и корректная работа увеличенного шрифта.
5. Архитектура остаётся в Gradle-модуле `:app`. Новый модуль `:core` **не создаётся**.
6. Финансовые расчёты и принятие решений отделены логически от Compose UI; UI не должен самостоятельно вычислять финансовые показатели.

## 2. Карта экранов

| ID | Экран / состояние | Вход | Нижняя навигация | Выход / действие |
|---|---|---|---|---|
| O1 | Обзор | Запуск; вкладка «Обзор» | Обзор · Данные · План | Финансовая оценка, показатели, детали, заключение, План/FIRE |
| O2 | Финансовая оценка | Балл на Обзоре | Нет | Разбивка баллов, экспорт оценки, детали, Назад |
| O3 | Все показатели | Кнопка на Обзоре; связанные действия | Нет | Категория/фильтр, деталь, экспорт результатов, Назад |
| O4 | Деталь показателя | Карточка Обзора, список, заключение/оценка | Нет | Назад; при наличии — к исходным данным |
| O5 | Финансовое заключение | Кнопка на Обзоре | Нет | Связанные детали, экспорт заключения, Назад |
| D1 | Данные | Вкладка «Данные» | Обзор · Данные · План | Аккордеоны, ввод, валюта, показатели |
| P1 | План / FIRE (реальное) | Вкладка «План», карточка FIRE | Обзор · Данные · План | Переключить режим, информация о расчёте |
| P2 | План / Симуляция | Переключатель режима | Обзор · Данные · План | Рычаги, события, сброс, подробности |
| P3 | План / раскрытые события | Аккордеон в P2 (это состояние P2) | Обзор · Данные · План | Выбор, ⓘ, снять чип, свернуть |
| P4 | Подробные результаты симуляции | Кнопка в P2 | Нет | Сравнение базового/сценарного результата, Назад |

На вторичных экранах (O2–O5 и P4) использовать верхнюю стрелку «Назад» и системный Back. По возвращении сохранять исходный экран, активный фильтр, раскрытые секции и позицию прокрутки. На главных экранах всегда **ровно три** пункта нижней навигации, независимо от состояния аккордеонов. У события нет отдельного пункта навигации.

## 3. O1 — Обзор (начальный экран)

Порядок контента:

1. **Общая финансовая оценка** — компактный гейдж, балл и понятный текст; нажатие ведёт на O2. Не переименовывать балл в «готовность к FIRE», если его методика шире.
2. **FIRE** — статус и срок/возраст, нажатие ведёт на P1 (именно реальный режим, даже если ранее был выбран P2).
3. **Денежный поток + норма сбережений** — совместная карточка этапа накопления; отдельные зоны или явные действия открывают соответствующие O4. Значения должны соответствовать реальным исходным данным.
4. **Финансовая подушка** — месяцы покрытия и переход на O4.
5. **Требует внимания** — не более двух самых значимых проблем из актуальной оценки/заключения. Выбирать детерминированно по существующим статусам и приоритетам; при равных приоритетах стабильный порядок. Не придумывать отсутствующие проблемы. Если проблем нет — нейтральное позитивное состояние, не пустая карточка.
6. Два перехода: **«Все показатели»** → O3; **«Финансовое заключение»** → O5.

Состояния карточки FIRE:

- `достижимо в будущем`: «До FIRE: N лет», прогнозный возраст;
- `цель достигнута`: **«Цель FIRE достигнута»** и пояснение в соответствии с реальной моделью;
- `недостижимо`: **«Недостижимо при текущих параметрах»**;
- `некорректные исходные данные / возраст`: существующее диагностическое сообщение; не представлять отсутствие результата как ноль лет.

Округление — только форматирование для UI, без изменения вычислений. Числа и статусы в макетах демонстрационные.

## 4. O2 — Финансовая оценка

Показывать полный общий балл, имеющуюся разбивку по компонентам, пороги и оценки. Каждая связанная метрика ведёт на O4. Сохранить **«Экспорт оценки»** в контексте этого экрана. Не заменять полную оценку только гейджем Обзора.

## 5. O3 — Все показатели

Представить существующие метрики без потерь. Группы/фильтры (горизонтальная прокрутка с очевидным индикатором продолжения): **Все**, **Денежный поток**, **Капитал и риски**, **Бенчмарки**. Строка: название, фактическое значение, статус, переход O4. Использовать единую систему статусов, включая текстовые метки (не один цвет). Сохранить **«Экспорт результатов»**.

Включить все существующие показатели из `MetricsScreen`, в том числе денежный поток, норму сбережений, резерв/подушку, долговой показатель, чистый капитал, Fidelity, CFS/KFS и реальную доходность; точный реестр сверить по действующему коду, не генерировать новые фиктивные метрики.

## 6. O4 — Деталь показателя

Это вторичный экран, **не четвёртая вкладка**. Унифицированный шаблон из применимых блоков: название, значение и единицы, текстовый статус, пороги со шкалой (если определены), формула с пояснением переменных (если существует), вклад в балл (если оценивается), заключение аудитора (если применимо), при необходимости переход к редактированию исходных данных. Отсутствующие блоки не выводить и не заменять выдуманными данными. Повторно использовать существующие вычисления и локализованные тексты.

## 7. O5 — Финансовое заключение

Сохранить полный текст и группировку существующего аудиторского заключения: положительные, нейтральные, отрицательные наблюдения; дисклеймер/допущения в понятном месте; связанные переходы O4 по надёжным ID показателей. Общие замечания без однозначной связи остаются обычным текстом. Кнопка **«Экспорт заключения»** здесь. Никаких трёх экспортных кнопок на Обзоре.

## 8. D1 — Данные

Пять аккордеонов с итоговыми значениями в заголовке:

1. **Доходы и расходы** (при первом посещении открыт): действующие поля, денежный поток и норма сбережений как вспомогательные вычисленные значения.
2. **Активы**: все существующие поля и варианты учёта резервов.
3. **Долги**: все существующие поля.
4. **Допущения модели**: доходность, инфляция, налоги и другие действующие параметры; явные пояснения ⓘ.
5. **Возраст**: исходный возраст/дата рождения, горизонт жизни и связанные значения.

Остальные аккордеоны при первом посещении закрыты. После взаимодействия сохранять раскрытие в рамках навигации. Валюта — компактный селектор вверху. Компактная строка живого результата: **балл · срок FIRE/статус · текущий поток**; она относится к вводу реальных данных, не к симуляции. Не перекрывать поля и системную клавиатуру; при маленьком экране/крупном шрифте разрешён перенос, сворачивание или незакреплённое расположение. Переход «Посмотреть показатели» ведёт на O3 (не на несуществующую старую вкладку).

## 9. P1 — План / FIRE (реальное)

Переключатель: **«FIRE (реальное)» | «Симуляция»**. При первом открытии Плана — P1. При обычном возврате во вкладку сохранять последний выбранный режим. Исключение: явный переход с FIRE-карточки Обзора открывает P1.

Показывать базовый срок/статус FIRE, возраст достижения, целевой капитал, параметры горизонта/реальной доходности и график прогноза; существующие формулировки достигнуто/недостижимо и обработку некорректных данных сохранять. **Не** показывать ползунки и переключатели сценариев в P1. Любой график относится к реальным данным; в Симуляции график остаётся скрытым согласно ранее принятому решению.

## 10. P2/P3 — План / Симуляция (оптимизированный B4)

Сверху, **в пределах контента Плана ниже переключателя режима**, закреплённая компактная панель результата:

- **Срок FIRE**: база → сценарий, разница при корректных числовых состояниях;
- **Возраст достижения FIRE**: база → сценарий, разница при корректных числовых состояниях;
- **Изменений: N**: количество активных ненулевых отклонений ползунков + включённых событий;
- **«Сбросить»**: сбрасывает только сценарий, не исходные данные; при нуле изменений отключена.

**Не показывать денежный поток в закреплённой панели или в подробном сравнении результатов симуляции.** Он остаётся действующей метрикой этапа накопления на Обзоре/Данных/в показателях и при необходимости может участвовать во внутренних расчётах.

Под панелью, в прокручиваемой части:

1. **Рычаги** — три существующих регулятора (дополнительный взнос/сбережения, расходы, доходность), с читаемым значением и понятной привязкой к базе. Не менять смысл и диапазон шкал без отдельной задачи.
2. **Выбрано** — чипы активных событий с удалением одним нажатием; если событий нет, строку скрывать.
3. **События** — аккордеоны «Благоприятные (7)» и «Неблагоприятные (7)»; внутри все действующие 14 сценариев. Каждая строка: название, краткое действие/эффект, Switch, ⓘ для подробного описания. Сохранить все существующие ID событий, формулы применения и допустимые комбинации.
4. **«Подробные результаты»** → P4.

Панель остаётся в поле зрения при прокрутке рычагов/событий, но не должна перекрывать переключатель режимов, системные панели или прокручиваемый контент. Высоту не фиксировать жёстко в 72dp; проверить 320dp, 360dp, 411dp и шрифт 1.0/1.3/1.6. При отсутствии изменений показывать базовое значение без искусственного выигрыша. Если базовый или сценарный FIRE достигнут либо недостижим, показывать осмысленный статус вместо разницы с неопределённым сроком.

Источник истины — единое состояние симуляции. Чип и Switch синхронизированы по одному идентификатору события. Реальные исходные данные не меняются. При переключении P2 → P1 → P2 активный сценарий сохраняется до явного сброса; перезапуск приложения не должен незаметно превращать сценарий в базовые данные. Политику долговременного хранения черновика сценария определить по текущему поведению, не менять её скрытно.

## 11. P4 — Подробные результаты симуляции

Сравнение **База / Сценарий** для: срока FIRE, возраста FIRE, целевого капитала FIRE **только если обе стороны корректно рассчитаны и сопоставимы**, а также пояснения изменения срока. Не добавлять денежный поток как итоговый KPI. Если цель достигнута или недостижима, показывать статусы вместо фиктивных чисел. Явное предупреждение: **«Симуляция не изменяет исходные данные»**. Числовые примеры в макетах не являются эталоном финансовой модели.

## 12. Навигация и состояния

| Действие | Результат |
|---|---|
| Запуск приложения | O1 Обзор; при первом запуске оставить ранее утверждённое однократное уведомление о примерных данных |
| Тап на общий балл | O2 Финансовая оценка |
| Тап на FIRE Обзора | P1 План/FIRE (реальное) |
| Тап на поток/норму/подушку | O4 конкретной метрики |
| «Все показатели» | O3 со стартовым фильтром «Все» |
| «Финансовое заключение» | O5 |
| Тап на связанную проблему | O4 по стабильному ID либо O5, если нет однозначной метрики |
| «Данные» | D1; состояние аккордеонов сохраняется после первого открытия |
| «Посмотреть показатели» из Данных | O3 |
| «План» из нижней навигации | Последний режим Плана; в первую навигацию P1 |
| Переключение режима Плана | P1 ↔ P2 без изменения базы и без сброса сценария |
| Открыть событие | P3 — состояние P2, нижняя навигация неизменна |
| «Подробные результаты» | P4, Назад возвращает P2 и позицию прокрутки |
| Back на O2/O3/O4/O5/P4 | Вернуться к точному источнику перехода и восстановить фильтр/прокрутку |
| Смена основной вкладки | Новое главное содержимое; вторичный стек не должен неожиданно перехватывать следующий Back |

При тапе на показатель из финансового заключения Back возвращает именно к заключению, а не к Обзору. Действия экспорта сохраняют прежнюю семантику и не меняют навигацию.

## 13. Форматирование, доступность, локализация

- Статус всегда поясняется текстом/иконкой, а не только цветом; сохранить утверждённые цветовые правила, включая красный `#B91C1C` в светлой теме и различимый нейтральный жёлтый.
- Сократить ложную точность («24,00» → «24» в обзорном представлении); необходимые точные значения доступны в деталях. Не округлять данные до вычислений.
- Размеры интерактивных целей, TalkBack-описания значений ползунков и статусных элементов, адаптация 320/360/411dp и шрифтов 1.0/1.3/1.6.
- Все пользовательские строки через существующую систему локализации RU/EN/DE/FR/IT/ES; проверка переносов и длинных чисел/валют.
- Режимы FIRE и Симуляции не смешивают реальную модель и сценарий визуально или семантически.
- Поддерживать экранные режимы loading/empty/invalid и избегать перекрытия закреплённых панелей системной клавиатурой.

## 14. Миграция на v2 — последовательность

**Рабочая ветка:** `feature/redesign-v2`, отдельно от стабильной `main`. Настроить `orchestrator/config.json` (в частности `branch`) перед запуском очереди. Слияние только после проверки.

| Этап | Область | Результат и gate |
|---|---|---|
| M0 | Зафиксировать текущую базу | Чистая ветка, контрольные числовые примеры, список существующих метрик, сценариев и экспортов |
| ARCH-01 | Аудит финансового ядра | Эталонные регрессионные тесты расчетов, FIRE-статусов и сценариев; существующий `unit` |
| ARCH-02 | Логическое разделение расчётов/UI | Composable отображают результаты из модели/ViewModel; **без** нового Gradle-модуля и без изменения формул; `unit` + `android` |
| M1 | Маршруты и оболочки O1–O5 | Новый стек и таблица соответствия без удаления старой функциональности; `android` + подходящие тесты |
| M2 | Обзор, оценка, каталог, детали, заключение | Все показатели и три экспорта доступны по новым путям; `unit` + `android` |
| M3 | Данные | Аккордеоны и живые показатели, сохранение полей/значений; `android` + тесты |
| M4 | План/FIRE/Симуляция | Оптимизированный B4, сценарии, закреплённые результаты, отдельные статусы; `unit` + `android` |
| M5 | Локализация и доступность | 6 языков, темы, экраны и размеры шрифтов; UI- и ручные проверки |
| M6 | Финальная приёмка | `--check full`, `--check release`, сравнение эталонных расчётов, сохранение данных после обновления, ручная проверка на устройстве; PR и merge |

**ARCH-03 (`:core`) исключён по решению владельца.** Не менять ID, fingerprint, статусы или SHA-256 механизмы оркестратора ради редизайна. Существующий профиль `--check core` отсутствует; не использовать его в задачах без реализации реального профиля.

Миграция пользовательских данных: оставить `applicationId`, ключи/формат локального хранения и совместимость установки поверх текущей версии. Проверить обновление на том же подписывающем ключе, реальные сохранённые данные и неизменность базовых вычислений. Новая структура экранов не является основанием для удаления старых пользовательских настроек.

## 15. Критерии приёмки

- [ ] Существуют три и только три нижних пункта; главная вкладка при запуске — Обзор.
- [ ] Все O1–O5, D1, P1–P4 доступны штатными путями, без тупиков и потерянных функций.
- [ ] Все существующие метрики и баллы отображаются в новой структуре с прежними результатами.
- [ ] Сохранены три экспорта и полное финансовое заключение.
- [ ] Реальный FIRE, достигнутый FIRE, недостижимый FIRE и невалидный возраст отображаются корректно.

## 16. Открытые вопросы исполнения, не меняющие утверждённую концепцию

1. Точное соответствие каждой существующей метрики экрану и её стабильный идентификатор — составить непосредственно по кодовой базе перед M1.
2. Для «двух главных проблем» — использовать действующую логику аудитора; если нет формального приоритета, закрепить детерминированный порядок без изменения оценок.
3. Политика сохранения незавершённой симуляции после перезапуска приложения — документировать действующее поведение и отдельно согласовать, если требуется изменение.
4. Состав и формат точных чисел в «Подробных результатах» — сверить с действующими типами `FireStatus` и `CalculatedMetrics`.
5. Если конкретный показатель не имеет формулы, порогов, баллов или комментария, соответствующий блок O4 скрывается.

Эти вопросы решаются в атомарных задачах реализации, не дают права произвольно менять утверждённую архитектуру или финансовые алгоритмы.
