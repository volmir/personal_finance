# Финансы и FIRE v2 — подробный план реализации и миграции

Основной источник UX-требований — `UIUX_V2_SPEC.md`. Этот документ является планом реализации, не заменяет утверждённые решения.

## A. Стратегия разработки

Создать от актуальной стабильной `main` ветку `feature/redesign-v2`. До запуска очереди привести `orchestrator/config.json` к этой ветке и проверить, что `push` и автоматические коммиты не затронут `main`. Открыть черновой Pull Request, в котором накапливаются проверки и замечания. Каждая логическая задача небольшая; действующие файлы пользователя и незавершённую очередь оркестратора не переписывать самовольно.

## B. Сначала финансовые расчёты

1. **ARCH-01 — аудит и фиксация ядра.** Составить список функций `FinanceCalculator`, `ProjectionEngine`, `FinancialMetricEvaluator`, `SimulatorScaleCalculator`, генератора аудита и моделей. Определить зависимости от UI/Android, фиксировать эталонные входы и выходы для обычного FIRE, достигнутого FIRE, недостижимости, граничного возраста, нулевого/отрицательного денежного потока, сценарных переключателей. Тесты должны сравнивать значения в допустимых математических погрешностях, а статусы — точно.
2. **ARCH-02 — логическое отделение.** Вычисления и правила финансовой оценки остаются в `domain` / моделях, `MainViewModel` предоставляет UI готовые значения и состояния, Compose-экраны лишь форматируют и отображают. Не менять финансовые формулы. Начинать с наблюдаемых вычислений, найденных в Composable, и переносить их под защитой тестов.
3. **ARCH-03 отменён.** Не создавать Gradle-модуль `:core`, не менять многомодульную структуру, не добавлять фиктивный `--check core`.

## C. Разбиение UI на атомарные этапы

### UI-01. Навигационный контракт

- Новый enum/маршруты `OVERVIEW`, `DATA`, `PLAN` и стек вторичных экранов.
- Отдельные destinations: `FINANCIAL_SCORE`, `ALL_METRICS`, `METRIC_DETAIL(metricId)`, `FINANCIAL_OPINION`, `SIM_RESULTS`.
- Back: восстановление предыдущего источника и scroll/filter/accordion. Bottom navigation только для трёх главных вкладок.
- Сохранить семантику существующего `currentTab` и действующее состояние до миграции; старые screen Composable не удалять на этом этапе.

### UI-02. Обзор

- Гейдж + балл, FIRE-карточка с корректными статусами, объединённые поток/норма, подушка, два приоритетных предупреждения, два перехода в полный каталог и заключение.
- Для выбора предупреждений использовать статусы из текущего аудитора; если требуется алгоритм ранжирования — задокументировать и покрыть тестами, но не менять вычисления.
- Значения на Обзоре только из реальных данных, не из временной симуляции.

### UI-03. Финансовая оценка, каталог и детали

- Перенести полную разбивку баллов из `AuditScoreScreen` на вторичный экран оценки.
- Сохранить набор метрик и фильтры `MetricsScreen`, включая бенчмарки, на экране всех показателей.
- Сделать универсальный `MetricDetail`, управляемый стабильным ID и метаданными метрики, но опциональные поля (формула, пороги, баллы, комментарий) показывать только при фактическом наличии.
- Не дублировать вычисления в UI; экспорты оценок и показателей привязать к своим экранам.

### UI-04. Финансовое заключение

- Перенести полное заключение аудитора из текущего экрана баллов; сохранить позитивные/нейтральные/отрицательные блоки и дисклеймер.
- Связанные с метриками заключения открывают `MetricDetail` по достоверному ID. Остальные остаются текстом.
- Сохранить `Экспорт заключения` и содержимое экспорта.

### UI-05. Данные

- Пять аккордеонов в утверждённом порядке. Первый раз раскрыть доходы/расходы, остальные свернуть.
- Перенести все действующие поля, валидацию, переключатель режима резерва, даты, валюту и подсказки, не теряя ни одной функции.
- Живая строка балл/FIRE/поток не перекрывает клавиатуру, поля и нижнюю навигацию; на маленьких экранах может переноситься/сворачиваться.
- Кнопка «Посмотреть показатели» открывает новый каталог.

### UI-06. План / FIRE

- Перенести исходный результат, целевой капитал, график и параметры из `FireRetirementScreen`.
- По умолчанию новый пользователь видит FIRE (реальное); возврат на План запоминает выбранный режим. Явный переход с карточки FIRE на Обзоре открывает реальный FIRE.
- Все ранее утверждённые формулировки статусов сохранить; график только в реальном режиме.

### UI-07. План / Симуляция и события

- Закреплённая панель ниже переключателя режима: срок, возраст, числовая разница/статус, счётчик, сброс. Денежный поток удалить из сценарных итогов.
- Три крупные шкалы со значениями. Все 14 существующих событий сохранить в двух группах по 7; чипы/переключатели синхронизировать через единый state.
- При нажатии ⓘ описание показывать в диалоге/bottom sheet, без дублирующего текста в каждой карточке.
- Кнопка подробностей открывает сравнение срока, возраста и *при сопоставимости* целевого капитала; не превращать расчёт в рекомендацию инвестиций.
- Обработать все состояния `FireStatus`, отсутствие численного возраста/срока, нулевые изменения, сброс, повторный вход и смену режима.

### UI-08. Полировка и доступность

- Согласовать компоненты с токенами тем, сохранить ранее утверждённые цвета и размеры.
- RU/EN/DE/FR/IT/ES, светлая и тёмная темы, TalkBack/контентные описания, шрифты 1.0/1.3/1.6 и ширины 320/360/411dp.
- Экранные тесты, снимки для публикации, проверка крупных чисел/других валют и нулевых состояний.

## D. Обязательные пользовательские маршруты (E2E)

| № | Сценарий | Критерий завершения |
|---|---|---|
| 1 | Запуск → Обзор → балл → Финансовая оценка → деталь → Back ×2 | Вернулись на Обзор; ничего не потеряно |
| 2 | Обзор → Все показатели → Бенчмарки → Real Return → Back | Восстановлены фильтр и прокрутка |
| 3 | Обзор → Требует внимания → деталь → исходные данные | Отредактирован нужный параметр, пересчитаны показатели |
| 4 | Обзор → Финансовое заключение → проблема → деталь → Back | Возврат именно в заключение |
| 5 | Обзор → FIRE-карточка | План открывается в режиме реального FIRE независимо от прежнего выбора |
| 6 | План → Симуляция → рычаг → событие → подробности → Back | Сохранились рычаг, событие и позиции прокрутки |
| 7 | Симуляция → FIRE → Симуляция | Черновик сценария сохранён; реальные данные неизменны |
| 8 | Симуляция → Сброс | Изменений 0; итоги совпали с базой; пользовательские данные не сброшены |
| 9 | Реальные данные соответствуют FIRE достигнут | Обзор и План показывают согласованный статус, не отрицательный срок |
| 10 | FIRE недостижим / возраст некорректен | Нет выдуманных сроков и арифметики с неопределённым результатом |
| 11 | Экспорт оценки, показателей и заключения | Формат и содержимое соответствуют текущему приложению |
| 12 | Обновление установленной v1 → v2 | Исходные данные, валюта, возраст, настройки и значения не потеряны |

## E. Контроль неизменности расчётов

Для набора эталонных входов сравнивать значения до/после миграции: поток, норму сбережений, резерв в месяцах, долг, чистый капитал, бенчмарки, оценки, срок и возраст FIRE, целевой капитал и эффекты всех 14 сценариев. При различии диагностика относится к регрессии, а не к «улучшению» алгоритма. Не менять расчётные формулы без отдельного решения владельца.

## F. Проверки и gates

В текущей конфигурации проекта доступны `android`, `unit`, `orchestrator`, `full`, `release`. Для Android UI применять `android`, для финансового состояния/сценариев `unit && android`, для проверки оркестратора — `orchestrator`, перед финальным слиянием — `full && release` и ручную установку. `core` не существует, использовать его нельзя. Отдельное `:core` не планируется.

## G. Слияние и откат

Не удалять старые экраны/маршруты до подтверждения полноты эквивалентов; удаление — отдельная задача после тестов. Предусмотреть откат Pull Request и сохранение стабильной `main`. Для обновления на реальном устройстве проверить совместимость `applicationId`, хранилища и подписи APK. Слияние в `main` разрешать после прохождения чек-листа из основного документа и ручной приёмки пользователем.

## H. Макеты и вёрстка

Макеты имеют единый логический размер 400 × 870 и экспортированы 2×. Это **один viewport** каждого экрана, а не искусственное обещание вместить всю прокручиваемую информацию. Верстка должна учитывать прокрутку, клавиатуру, состояние развёрнутых секций и разные размеры шрифта. Пороги/числа демонстрационные; источник истины для значений — действующие доменные модели. SVG можно использовать для точных визуальных ориентиров, но не копировать его как реализацию Compose.
