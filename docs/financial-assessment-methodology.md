# Методика комплексной финансовой оценки

Статус документа: утверждённая целевая спецификация для очереди FA-01–FA-11. Это постоянное описание согласованных правил, а не одноразовый инструмент и не заявление о том, что методика уже реализована или выпущена. Реализация выполняется отдельными задачами очереди; до неё опубликованные версии и их артефакты не меняются.

## 1. Шкала, показатели и веса

Используются целые индивидуальные баллы от 0 до 10. Общий балл показывается с одним десятичным знаком. Есть девять показателей со стабильными ID, в следующем порядке исходных метрик:

| ID | Показатель | Вес, % |
|---|---|---:|
| `cash_flow` | денежный поток | 5 |
| `savings_rate` | норма сбережений | 20 |
| `emergency_fund` | резервный фонд | 5 |
| `safety_months` | запас месяцев | 20 |
| `debt_ratio` | долговая нагрузка | 10 |
| `net_worth` | чистый капитал | 5 |
| `fidelity` | Fidelity | 10 |
| `cfs` | КФС | 25 |
| `real_return` | реальная доходность | 0 |

Группы и их веса:

- `BUDGET` — 25%: `cash_flow`, `savings_rate`;
- `RESERVE` — 25%: `emergency_fund`, `safety_months`;
- `DEBT` — 15%: `debt_ratio`, `net_worth`;
- `CAPITAL` — 35%: `fidelity`, `cfs`.

`real_return` — отдельный параметр прогноза, не пятая взвешенная группа. Веса не изменяются по инициативе агента и не настраиваются пользователем. Это авторская эвристика, не научно валидированная шкала. Долговые и капитальные показатели частично коррелируют; разделение веса не означает независимость.

## 2. Показатели и правила баллов

Существующие пороги `FinancialMetricEvaluator` для `savings_rate`, `safety_months`, `debt_ratio` и `cfs` сохраняются. `emergency_fund` получает балл `safety_months`; отдельные 5% к 25% группы не добавляются.

### Денежный поток

`cash_flow <= 0` получает 0. При положительном денежном потоке и положительном доходе используется `savingsRate` в процентах:

- `<= 20` — 8;
- `> 20` и `< 50` — 9;
- `>= 50` — 10.

При положительном денежном потоке и нулевом доходе оценка недоступна: знаменатель отсутствует. Порогов абсолютных денежных сумм нет. Существующий raw-статус денежного потока по знаку сохраняется: положительный поток зелёный, но `savings_rate` при этом может быть нейтральным.

### Чистый капитал

- `< 0` — 0;
- `== 0` — 5;
- при положительном капитале доля `netWorth / totalAssets`:
  - `< 0.25` — 6;
  - `[0.25, 0.5)` — 7;
  - `[0.5, 0.7)` — 8;
  - `[0.7, 0.9)` — 9;
  - `>= 0.9` — 10.

Комбинация `netWorth > 0` и `totalAssets <= 0` считается недоступной как неконсистентная. Правило raw-статуса `net worth` не меняется: `>= 50%` активов — положительный статус и используется на Input, Metrics и Audit.

### Fidelity

`ratio = fidelityCapital / fidelityTarget`. Оценка недоступна при `!isAgeValid` или `target <= 0`. При доступности применяются именно значения ratio, а не проценты и не округлённый отображаемый текст:

| Условие ratio | Балл |
|---|---:|
| `<= 0` | 0 |
| `(0, 0.2)` | 2 |
| `[0.2, 0.4)` | 3 |
| `[0.4, 0.7)` | 4 |
| `[0.7, 0.8)` | 5 |
| `[0.8, 0.9)` | 6 |
| `[0.9, 1.0)` | 7 |
| `[1.0, 1.2)` | 8 |
| `[1.2, 1.5)` | 9 |
| `>= 1.5` | 10 |

Формула капитала Fidelity остаётся общей с FIRE: ликвидные и финансовые активы минус `max(0, liabilities - property)`.

### Реальная доходность

Реальная доходность задаётся в процентах, не в долях:

| Условие | Балл |
|---|---:|
| `< -5` | 0 |
| `[-5, -2)` | 2 |
| `[-2, 0)` | 4 |
| `== 0` | 6 |
| `(0, 2)` | 8 |
| `[2, 4)` | 9 |
| `>= 4` | 10 |

Это исключительно условный балл введённой прогнозной предпосылки, а не проверка достижимости или риска доходности. Изменение ожидаемой доходности или инфляции при прочих равных не меняет итоговый балл. `real_return` не используется для выбора сильных сторон текущего положения, cap, покрытия или нормализации. В аудите он обозначается как «Параметр прогноза · не входит в итог»; нельзя утверждать, что будущий доход гарантирован. Нечисловое или невалидное значение недоступно. Предусмотренная приложением нижняя граница `-50%` сохраняется.

## 3. Недоступные значения и особые случаи

Индивидуальный балл nullable. Недоступность не превращается в 0, 10, NaN или хороший балл и не приравнивается к негативному статусу.

- При `monthlyExpenses == 0` не оцениваются `safety_months`, `emergency_fund` и `cfs`, потому что нормировка на расходы невозможна. Исходные расчётные значения и специальные случаи FinanceCalculator, включая прежние условные 12/30, не меняются.
- При `income == 0` и `expenses > 0` сохраняются существующие `cash flow`/`savings rate` и отрицательная оценка: показатели отражают дефицит, а не поведение человека. Fidelity недоступен.
- При `income == expenses == 0` `savings rate` и `cash flow` недоступны для оценки, хотя старые raw-статусы метрик по нулю сохраняются.
- При `totalAssets == 0` и `liabilities == 0` `debt_ratio` сохраняет 10, а `net_worth` — 5.
- При `liabilities > 0` и `assets == 0` `debt_ratio == +Infinity` — валидный критический случай с 0 баллов, а не missing.

Существующий clamp входных данных не меняется. Нули денежных сумм сравниваются с учётом действующей денежной точности, без опасного сравнения сумм Double как сырого равенства.

## 4. Агрегация, покрытие и итоговый статус

Для каждой группы вычисляется только по доступным взвешенным показателям:

`G = sum(weight_i * score_i) / sum(weight_i)`.

Вес группы остаётся соответственно 25/25/15/35, даже если часть её показателей недоступна. Если вся группа недоступна, она исключается, а итог пересчитывается по оставшимся весам групп:

`Raw = sum(groupWeight * G) / sum(groupWeight)`.

Покрытие — сумма исходных весов доступных показателей, без `real_return`, от 0 до 100%. Оно не означает количество показателей или достоверность. При покрытии менее 100% показываются «Неполная оценка» и процент покрытия, например 90%. Сравнение полного и неполного балла условно; это явно сообщается в методике.

Если одновременно `income == 0`, `expenses == 0`, `totalAssets == 0` и `liabilities == 0`, либо нет ни одной доступной группы, общий балл недоступен (отдельный nullable/флаг). Gauge, badge и экспорт не показывают подставной балл. Доступные компоненты при нулевых суммах могут отображаться с пояснениями.

### Cap и округление

Cap при `cfsScore < 5` удаляется. Raw ограничивается сверху 6.0 только при `netWorth < 0` или `(totalAssets == 0 && liabilities > 0)`. Других cap нет; двойное наказание не добавляется. Группы заранее не округляются. После cap итог округляется `HALF_UP` до одного десятичного знака.

Порог итогового статуса сохраняется:

- `< 3.5` — красный;
- `[3.5, 7)` — жёлтый;
- `[7, 8.5)` — зелёный, «хорошее»;
- `>= 8.5` — зелёный, «отличное».

Для компонентного статуса сохраняются интервалы 0–4 красный, 5–7 жёлтый, 8–10 зелёный. Недоступность имеет отдельную отметку без оценочного цвета. Raw-значение коэффициента и невозможность его оценить должны быть явно различены.

## 5. Пенсионеры, дефицит и FIRE

В исходных данных нет признака стадии жизни и источника покрытия расходов. Нельзя вводить новый пользовательский ввод, определять пенсионера по возрасту или моделируемому `fireStatus`, либо снимать штраф из-за оптимистичного прогноза.

Оценка текущего денежного потока сохраняется. При дефиците в выводе используется смысл: «расходы превышают указанный доход; при плановом расходовании накоплений это не обязательно признак проблемы». Нельзя утверждать, что пользователь плохо управляет бюджетом, или автоматически советовать сокращать расходы. При нулевом доходе Fidelity — N/A.

Реальный FIRE остаётся отдельным расчётом и не доказывает финансовую независимость в текущей оценке. КФС включает имущество и не гарантирует жизнь на доход от капитала. Формулы Fidelity/FIRE, налог, входные формулы, хранилище и сценарии в FA-01–FA-11 не изменяются.

## 6. UI и краткий итог

Экран №3 содержит единую итоговую карточку и существующие группы аудита. Отдельного блока четырёх баллов и его progress bar больше нет. Малый балл находится справа в карточке показателя; существующий текст сохраняется. Все девять ID отображаются. Недоступные показатели попадают в отдельную секцию только при наличии. `real_return` показывается с пометкой и без вклада в итог.

Глобальные badge и gauge синхронны. При неполных данных явно показываются покрытие и предупреждение. При отсутствии итоговой оценки показывается нейтральная локализованная надпись.

Краткий итог динамический, локальный, без ИИ и сети: общий статус, до двух значимых сильных сторон и до двух рисков/приоритетов из разных групп, без повторов и ложных советов. Критический отрицательный капитал и дефицит бюджета приоритетнее обычных рисков; фразы короткие и основаны на реальных данных. Реальная доходность находится в отдельном пояснении, не среди сильных сторон текущего положения. Точные алгоритмы ранжирования и правила пустых наборов закрепляются FA-05.

## 7. Экспорты

Все экспорты используют base metrics, текущие `Formatters`, Android share intent, дисклеймеры и все шесть локалей. Опубликованные релизы не меняются.

1. **«Экспорт оценки»** — общий балл или недоступность, краткий итог, индивидуальные баллы с N/A и `real_return` вне итога, фактические показатели и FIRE из прежнего отчёта.
2. **«Экспорт финансового аудита»** — качественный итог и тексты аудита, без общего и индивидуальных баллов, весов и числового покрытия. Фактические суммы, проценты и коэффициенты остаются.
3. **«Экспорт результатов»** — исходные данные и метрики, комплексный балл, индивидуальные баллы и существующий блок FIRE.

## 8. Границы FA-01–FA-11

Эта спецификация является согласованной целевой методикой. В FA-* разрешены только изменения, необходимые для её последовательной реализации, с сохранением прочих frozen decisions корневого `AGENTS.md` и UI test matrix budget. Не меняются автоматически `versionName`/`versionCode`, теги, APK, F-Droid, screenshots/metadata опубликованных версий, зависимости, конфигурация orchestrator и `PROGRESS.md`. Последующая очередь FIRE-M* изменяет только отдельно согласованные правила FIRE.
