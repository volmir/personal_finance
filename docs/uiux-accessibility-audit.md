Дата: 2026-11-13. Ветка `auto/tasks` не трогалась. Исходники, ресурсы, тесты и Gradle **не изменены** (единственный новый файл — этот отчёт).

## 0. Метод и честные ограничения

- **Эмулятора/ADB с устройством нет.** Проверено: `adb devices` — пусто, каталога `emulator/` и `system-images/` в SDK нет. Ни один сценарий ниже не «проверен на устройстве».
- Gradle-тесты в рамках этой задачи **не запускались** (-аудит, а не верификация фиксов). Существующие тесты читались статически.
- Всё ниже — **статическая проверка разметки/строк/тестов**. Где вывод следует напрямую из кода (например, отсутствие `semantics` у Canvas, фиксированная высота 30 dp) — статус «подтверждено кодом». Где вывод зависит от реального рендера (обрезка текста, TalkBack-поведение) — статус «статический прогноз, нужен ручной тест». Гипотезы не выдаются за дефекты.
- Рабочая ширина контента: экраны используют `LazyColumn` с горизонтальным паддингом 16+16 dp и карточки с паддингом 12–16 dp, т.е. при ширине экрана **320 dp доступно ≈264–272 dp**, при **360 dp ≈304–312 dp** (оценка по коду, без рендера).

## 2. Что подтверждено как корректное (не проблемы)

- Нижняя навигация: ровно 4 вкладки в порядке INPUT/METRICS/SCORES/FIRE (`ApprovedUiRegressionTest` фиксирует порядок); у каждой `NavigationBarItem` есть иконка с `contentDescription = tab.localizedTitle(strings)` и видимая подпись (`FinanceApp.kt:182-204`).
- Подвкладки FIRE: переключаются через `selectable(selected, role = Role.Tab, ...)` (`FireRetirementScreen.kt:1157-1161`) — это правильная семантика вкладок; в «Симуляции» действительно нет графика (график, параметры и дисклеймер рендерятся только при `!isSimulationSubtab`, `FireRetirementScreen.kt:469-504, 998-1092`).
- Горизонтальная прокрутка фильтров: один `Row` с `horizontalScroll(rememberScrollState())` и `testTag("metrics_filter_row")` (`MetricsScreen.kt:127-133`); аналогично валютные чипы на Input (`InputDataScreen.kt:125-154`). Вертикальный скролл — `LazyColumn` на всех экранах (важно при fontScale).
- Основные кнопки (`SecondaryActionButton`) имеют `defaultMinSize(minHeight = 48.dp)` (`SecondaryActionButton.kt:43`); иконка share в шапке Аудита — `size(48.dp)` (`AuditScoreScreen.kt:147-149`).
- Статусные тексты в обеих темах идут через `StatusColors.getReadableTextColor/getTextColor` с отдельными light/dark оттенками; юнит-тесты на контраст существуют (`StatusTextContrastTest.kt`, `StatusTextColorUsageRobolectricTest.kt`) — их результат в этой задаче не запускался, сам факт наличия тестов отмечен статически.
- Декоративные иконки корректно помечены `contentDescription = null` (заголовки карточек, иконки секций) — это правильно, а не пропуск.
- Диалог `SampleDataNoticeDialog` — стандартный M3 `AlertDialog` с одним подтверждением (`FinanceApp.kt:273-285`).

## 3. Проблемы (подтверждённые кодом — П1; прогнозы — П2/П3)

### Q01. Кнопка «Сброс» симулятора 30 dp — ниже минимального touch target
- Экран/компонент/файл: FIRE → «Симуляция» → шапка симулятора, `OutlinedButton` «Сброс», `app/src/main/java/com/example/ui/screens/FireRetirementScreen.kt:668-675`.
- Условия: любая ширина, любая тема; видна только при активных изменениях (`if (isSimulating)`).
- Проблема/риск: `Modifier.height(30.dp)` — высота тач-цели 30 dp против ~48 dp. При fontScale 1.3–1.5 текст кнопки 11 sp может визуально не влезать в 30 dp и/или обрезаться. Остальные кнопки приложения — 48 dp (`SecondaryActionButton`), эта — единственное исключение.
- Приоритет: **P1** (подтверждено кодом, прямая доступность).
- Рекомендация: на согласование — привести к единому минимуму высоты (например, `defaultMinSize(minHeight = 48.dp)` как в `SecondaryActionButton`) без изменения логики сброса.
- Статус: **подтверждено кодом; на устройстве не проверялось** (рендер при fontScale 1.3/1.5 нужен для подтверждения обрезки текста).

### Q02. График траектории капитала полностью недоступен для TalkBack (Canvas без семантики)
- Экран/компонент/файл: FIRE → подвкладка FIRE → карточка траектории, `FireTrajectoryChart`, `app/src/main/java/com/example/ui/components/FireTrajectoryChart.kt:66-248` (ветка `Canvas` 129-220, легенда 72-103, подписи осей 224-247).
- Условия: любой сценарий; критично для пользователей TalkBack.
- Проблема/риск: в компоненте нет ни одного `semantics`/`contentDescription`. Точки легенды (`Box` 10 dp) и весь Canvas невидимы для скринридера; останется только текстовый max-сумма и подписи осей. Пользователь TalkBack не узнает ни значения точки выхода на пенсию, ни тренда. Аналогично `ScoreGauge` (`ScoreGauge.kt:51-99`): дуга на Canvas без семантики, хотя числовое значение — отдельный `Text` и читается.
- Приоритет: **P1** (отсутствие семантики подтверждено кодом).
- Рекомендация: на согласование — добавить текстовую сводку графика (точка выхода на пенсию, накопленный/требуемый капитал), видимую или скрыную для TalkBack, и/или `contentDescription` на контейнер графика в едином месте (`FireTrajectoryChart`), не меняя саму отрисовку. Окончательный вид сводки — согласовать (это новый текст во всех 6 языках).
- Статус: **подтверждено кодом (отсутствие семантики); TalkBack-поведение — статический прогноз, нужен ручной тест с TalkBack**.

### Q03. Слайдеры симулятора не подписаны для TalkBack осмысленно
- Экран/компонент/файл: FIRE → «Симуляция», три `Slider` (`FireRetirementScreen.kt:744, 848, 937`), подписи — отдельные `Text` над слайдерами (`fireSliderSavings/Expenses/Return`), min/step/max — `Text` 10 sp под слайдерами.
- Условия: TalkBack + слайдеры; ширины 320/360 dp; fontScale 1.3/1.5.
- Проблема/риск: у `Slider` нет явного `contentDescription`/метки, связывающей слайдер с его «Сбережения/Расходы/Доходность» и с текущим значением в валюте/%. TalkBack по умолчанию объявляет позицию слайдера дробью, а не денежное значение; соседние текстовые значения (например, `formatMoney(currentEffectiveSavings)`) не объединены семантически. delta-подписи («+X ₽ от базы…», факторы сценариев) — длинные строки на 10 sp.
- Приоритет: **P2** (высоковероятный риск; точная озвучка зависит от версии TalkBack/M3).
- Рекомендация: на согласование — задать слайдерам семантические подписи (название + текущее значение) через `contentDescription`/`semantics` и проверить порядок фокуса; текст подписей — в 6 языков.
- Статус: **статический прогноз, нужен ручной тест с TalkBack**.

### Q04. Нижняя навигация: длинные short-подписи на 11 sp при 320 dp и fontScale ≥1.3
- Экран/компонент/файл: `FinanceApp.kt:182-205` (`NavigationBarItem`, подпись 11 sp), строки в `Strings*.kt` (`tabScoresShort`, `tabFireShort`).
- Условия: ширина 320 dp (ячейка ≈80 dp), fontScale 1.3/1.5, языки DE («Bewertung & Audit» — 17 символов), RU («Итоги и Баллы» — 13), EN/FR/ES/IT (13–14). Расчётная ширина текста при 11 sp: DE ≈103 dp (≈134 dp при 1.3, ≈154 dp при 1.5), RU ≈79 dp (≈102/118 dp) — превышает ячейку.
- Проблема/риск: подпись может обрезаться/переноситься (у `NavigationBarItem` нет явного `maxLines`/`ellipsis` в коде), высота нижней панели может «прыгать» между языками; иконка + подпись при fontScale 1.5 займут больше высоты.
- Приоритет: **P2** (расчётный прогноз; реальный механизм обрезки зависит от M3).
- Рекомендация: на согласование — зафиксировать поведение подписи при переполнении (одна строка + ellipsis, либо двухстрочность) и проверить на 320 dp × fontScale 1.3/1.5 во всех 6 языках; возможно — пересмотреть DE-формулировку короткой подписи (но это смена утверждённой строки — только через согласование).
- Статус: **статический прогноз, нужен ручной тест (скриншоты 320/360 dp × fontScale × 6 языков)**.

### Q05. Карточки показателей и подсказки: кликабельная вся карточка без Role и без состояния «развёрнуто»
- Экран/компонент/файл: `MetricCard` (`MetricCard.kt:67-79`, `.clickable { expanded = !expanded }`), `CategoryBreakdownHint` (`InputDataScreen.kt:790-798`, `.clickable { isExpanded = !isExpanded }`), карточки сценариев (`ScenarioTogglesPanel.kt:476-484`, `.clickable { onToggle() }`).
- Условия: TalkBack; все экраны.
- Проблема/риск: нет `role = Role.Button` и нет семантики состояния (expanded/selected) — TalkBack объявляет клик без обозначения «кнопка» и без «развёрнуто/свёрнуто». Внутренняя иконка expand в `MetricCard` имеет `contentDescription` («развернуть/свернуть», `MetricCard.kt:216`), но она — отдельный узел внутри кликабельной карточки: фокус может дублироваться (карточка + иконка). У сценариев кликабельная карточка + внутренний `Switch` — два узла переключения на один элемент.
- Приоритет: **P2** (подтверждено отсутствием Role/состояния в коде; качество озвучки — прогноз).
- Рекомендация: на согласование — добавить `role` и состояние (`stateDescription`/expanded) единообразно в трёх компонентах и убрать дублирующих узлов; проверить порядок фокуса с TalkBack.
- Статус: **код подтверждает отсутствие Role/состояния; озвучка — статический прогноз, нужен ручной тест**.

### Q06. Бейдж симуляции и сводные строки при 320 dp / fontScale: обрезка без многоточия
- Экран/компонент/файл: hero-бейдж (`FireRetirementScreen.kt:307-326`, `widthIn(max = 112.dp)`, `maxLines = 3`, текст 10 sp); бейдж сводки симуляции (`:551-566`, `maxLines = 1`, `softWrap = false`); сводные строки «X ➔ Y» (`:588-628`, `Arrangement.SpaceBetween`, правая колонка без `weight`).
- Условия: 320 dp, fontScale 1.3/1.5, длинные суммы в валюте (например, `1 234 567 ₽ ➔ 2 345 678 ₽`), DE/FR.
- Проблема/риск: у бейджа сводки `maxLines = 1 + softWrap = false` без `ellipsis` — текст может обрезаться резко по правому краю; у сводных строк правая часть длиннее левой при SpaceBetween — обе части без ограничения ширины, возможен наезд/обрезка. Hero-бейдж ограничен 112 dp и 3 строками.
- Приоритет: **P2** (прогноз по разметке).
- Рекомендация: на согласование — определить допустимое поведение (перенос на две строки / ellipsis / уменьшение кегля), проверить на 320 dp × fontScale 1.5 с максимальными суммами.
- Статус: **статический прогноз, нужен ручной тест**.

### Q07. Легенда графика и подписи осей при fontScale 1.3–1.5
- Экран/компонент/файл: `FireTrajectoryChart.kt:72-103` (легенда — `Row` без `wrap`), подписи осей `:224-247` (`Row` с `weight(1f)` спейсерами).

- Статус: **статический прогноз, нужен ручной тест**.

### Q12. Фиксированные высоты при fontScale: график 180 dp, калибр 170 dp, высота прогресс-баров 6 dp
- Экран/компонент/файл: `FireTrajectoryChart.kt:114` (`.height(180.dp)`), `ScoreGauge.kt:53-55` (`.size(170.dp)` в `AuditScoreScreen.kt:162-167`), прогресс-баров 6 dp.
- Условия: fontScale 1.5; 320 dp.
- Проблема/риск: график и калибр имеют фиксированный размер — текстовые элементы внутри калибра (32 sp) при 1.5× занимают больше места, но остаются внутри 170 dp по оценке; подписи графика — вне фиксированной области и не обрезаются. ## 4. Отдельно проверено и дефектов не найдено (по коду)

- Тёмная тема: обе схемы определены, выбор по системной теме, `dynamicColor = false` — сторонние обои не ломают палитру; статусные тексты используют theme-зависимые оттенки. Тесты контраста существуют (не запускались здесь).
- Горизонтальная прокрутка: фильтры Metrics и валютные чипы Input — единственный горизонтальный скролл; системной горизонтальной прокрутки экранов нет.
- Валютные чипы: `FilterChip` с кликом, тест-теги `currency_chip_*` — TalkBack-доступ есть по умолчанию из M3.
- Диалог семпла-данных: стандартный `AlertDialog`, фокус удерживается диалогом, единственный confirm — допустимо.
- Вертикальные списки: `LazyColumn` на всех 4 экранах — длинный контент и крупный шрифт не обрезаются по высоте.

## 6. Общий вывод

Приложение статически адаптивно по каркасу: вертикальные списки, одна горизонтальная прокрутка для фильтров и валют, корректные подписи навигации и вкладок FIRE, 48 dp у основных кнопок. Главные риски — не каркас, а детали: недоступный график для TalkBack (Q02), несвязанные слайдеры (Q03), мелкая кнопка сброса (Q01), отсутствие Role/состояния у кликабельных карточек (Q05) и обрезки длинных перекрученных строк на 320 dp при крупном шрифте (Q04, Q06–Q08). Всё это — кандидаты на согласование, а не на самостоятельные правки: большинство требует новых строк в 6 языках или изменения утверждённых формулировок.
