# Финансы и FIRE v2 — очередь редизайна C + оптимизированный B4

> Это готовое содержимое для `orchestrator/TASKS.md` **после** подготовки ветки `feature/redesign-v2`. Очередь последовательная; формат не поддерживает поле `depends_on`, поэтому зависимости выражены порядком задач и условиями внутри промптов.
>
> Версия концепции: 21.11.2026. Полный контракт уже находится в репозитории: `docs/redesign_v2/UIUX_V2_SPEC.md`, `docs/redesign_v2/IMPLEMENTATION_PLAN.md` и карта точных ссылок на все 10 PNG/SVG в `docs/redesign_v2/README.md`. Макеты являются визуальными ориентирами, а действующие Kotlin-модели — источником математической истины.
>
> **Подготовка владельцем до запуска**: проверить ветку `feature/redesign-v2`, коммит документов, очереди и `config.json`; запустить `bash orchestrator/run.sh --backend opencode --models free --dry-run`. Не запускать очередь на `main`. Конфиг и TASKS защищены SHA-256 в ходе работы агентов: сами задачи не должны изменять их. Для OpenCode: `bash orchestrator/run.sh --backend opencode --models free` (если выбранный набор моделей доступен).
>
> **Общий контракт каждой задачи**: исследовать действующий код и корневой `AGENTS.md` перед редактированием; делать минимальные локальные изменения; не менять формулы, пороги, веса, финансовые статусы и результаты; не трогать `orchestrator/`, Gradle-модуль `:core` не создавать; сохранять шестиязычную локализацию, обе темы, `applicationId`, сохранённые данные, экспорт и существующие `testTag` по возможности; новые тесты писать там, где меняется поведение; при отсутствии необходимых данных/полномочий завершать `BLOCKED:` с точной причиной; не выполнять git commit/push самостоятельно (это делает оркестратор). Макеты показывают демонстрационные цифры, но не определяют финансовые результаты.
>
> **Цветовой контракт — обязателен на всех этапах**: `AuditIndicatorStatus.POSITIVE` → `SuccessGreen` (`#10B981`); `NEUTRAL` → `WarningYellow` (`#F59E0B`); `NEGATIVE` → `AlertRed` (`#EF4444`). Для текста применять `StatusColors.getTextColor(...)`, а не базовые акцентные значения: светлая тема `#047857`, `#856800`, `#B91C1C`; тёмная тема `#34D399`, `#FACC15`, `#F87171` соответственно. Для общего балла использовать `ScoreColorEvaluator` и фактические пороги `FinancialMetricEvaluator`, а не фиксированную зелёную дугу из макета. **6,7 — нейтральный (жёлтый), не позитивный.** Цвета нетематических декоративных элементов брать из существующей Emerald Material 3 темы. Статус сопровождается текстом/значком; не кодировать смысл одним цветом. Не подменять отчётливый жёлтый коричнево-красным оттенком. Обязательно контраст в обеих темах.
