# Проверка модуля оркестратора

Здесь фиксируются реальные прогоны модуля: автотесты, режим проверок
и живые запуски с настоящими CLI-агентами. Тесты выполнения работают
с временными репозиториями и подменяют агентов заглушками: они проверяют
поведение оркестратора, а не качество генерируемого моделями кода.

## 2026-11-13: мультибэкенд и профили проверок из конфига

Среда: Linux, локальный Git-проект с установленным модулем, Python 3,
авторизованные `codex` и `opencode`.

Код:

- `bash orchestrator/run.sh --check orchestrator` — **78 тестов, OK**
  (77 до Этапа 2; добавлены юнит-тесты валидации `checks`).
- `bash -n orchestrator/run.sh`, `python3 -m py_compile` всех файлов
  модуля — успешно.
- `bash orchestrator/run.sh --check --help` печатает список профилей
  динамически: встроенный `orchestrator` плюс профили из ключа `checks`
  конфига; `--check` без аргумента выбирает профиль `full`; неизвестный
  и пустой профиль — код 2 без выполнения команд.
- Новый тест интеграции gate: подменённый `python3` делегирует вызовы
  `checks.py` настоящему интерпретатору, профили резолвятся из конфига
  тестового корня; режим `--check` по-прежнему не требует чистого дерева,
  не читает очередь и не трогает блокировку.

Живой прогон бэкенда OpenCode (смоук SMOKE-01, tier `light`):

- Отдельный конфиг `backend="opencode"`; задача-зонд в очереди, gate —
  полный профиль проекта установки.
- Полный цикл с первой попытки: `opencode run --agent build --format json
  --model opencode/glm-5.3-flash-free` → gate прошёл → коммит → запись
  журнала; контрольная точка удалена, рабочее дерево чистое. Промпт подан
  через stdin; финальный ответ извлечён как последний text-event.
- Отдельно проверено: `opencode run` читает промпт из stdin (пайп и файл).
- Защита служебных файлов подтверждена живым прогоном: первая версия
  зонда целила README внутри `orchestrator/` и была остановлена
  с сохранением правок без коммита; после переноса цели вне каталога
  цикл прошёл.

## 2026-11-10: возобновление после прерываний

Прогон в исходном проекте установки модуля; проверки профиля `full`
этого проекта (обе Python-серии плюс его полный гейт) прошли успешно.

- `bash -n orchestrator/run.sh`, `git diff --check` — успешно.
- `--check orchestrator` — 64 теста, успешно.
- Полный профиль проекта установки: 81 тест его инструментов и 64 теста
  оркестратора, затем его проверочная команда — успешно.
- `--dry-run --only ID` подтверждает следующую незавершённую задачу,
  не запуская настоящего агента и не меняя журнал.

Синтетические интеграционные сценарии: сохранение частичных правок,
продолжение после SIGTERM, повтор после ошибки/пустого ответа/таймаута
агента, таймаут и прерывание gate без повторного вызова агента,
восстановление после отказа commit hook и остановки после состоявшегося
коммита, повтор push перед следующей задачей, пропуск завершённых задач,
защита от второго агента после SIGKILL родителя при удержании блокировки.
Смена задания, ветки/HEAD, защищённых файлов и повреждённая контрольная
точка останавливают восстановление; `BLOCKED:` не перезапускается.
Время сброса лимита проверено с явно заданным временем; ожидания настоящих
лимитов не выполнялись.

## Не проверялось

- Запуски реальных моделей на tier `standard`/`heavy` для обоих бэкендов
  и качество их работы: зависят от аккаунта и окружения пользователя.
- Формат сообщений об исчерпании квоты OpenCode: парсер лимитов пока общий
  (`try again at ...`); при первом реальном упоре в квоту дополнить.
- Удалённый push по SSH/HTTPS (проверен только локальный remote), Docker
  (`gate_base`), macOS и WSL.
- Приложение целевого проекта: установка модуля не меняет его код; проверку
  самого проекта выполняет его собственный профиль `checks`.

Первый реальный запуск в новом проекте: добавьте согласованную задачу
в `TASKS.md`, сохраните коммитом и выполните `bash orchestrator/run.sh
--only ID`.
