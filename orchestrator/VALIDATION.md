# Проверка интеграции в «Составь слова»

## Возобновление после прерываний — 10 ноября 2026 года

- `bash -n orchestrator/run.sh`, `git diff --check` — успешно.
- `bash orchestrator/run.sh --check orchestrator` — 64 теста, успешно.
- `bash orchestrator/run.sh --check full` — 81 тест инструментов и 64 теста
  оркестратора, затем `:core:test :app:assembleDebug` — `BUILD SUCCESSFUL`.
  Gradle использовал сохранённый результат `:core:test`; debug APK доступен.
- `--dry-run --only CORE-03` подтверждает следующую незавершённую задачу,
  не запуская настоящего агента и не меняя журнал кампании.

Синтетические интеграционные сценарии проверяют сохранение частичных правок,
продолжение после SIGTERM, повтор после ошибки/пустого ответа/таймаута агента,
таймаут и прерывание gate без повторного вызова агента, восстановление после
отказа commit hook и остановки после состоявшегося коммита, повтор push перед
следующей задачей. Проверены пропуск завершённых задач и защита от второго
агента после SIGKILL родительского процесса, пока оставшийся процесс удерживает
блокировку. Смена задания, ветки/HEAD, защищённых файлов и повреждённая
контрольная точка останавливают восстановление. `BLOCKED:` не перезапускается.

Ожидание отказа при повторном запуске после ошибки commit hook изменено:
теперь после устранения причины повторяются gate и коммит без нового вызова
агента. Незакоммиченный журнал без собственной контрольной точки по-прежнему
не считается завершением задачи. Время сброса лимита проверено с явно заданным
временем; ожидания настоящих лимитов и запуски реальных моделей не выполнялись.
Lint, release и устройство не проверялись: изменения касаются оркестратора.

## Предыдущая проверка интеграции

Дата: 9 ноября 2026 года. Очередь и проверки используют одну точку входа
`run.sh`. В `examples/` оставлен один файл задач — `TASKS.md`.

## Выполнено

```text
bash orchestrator/run.sh --check orchestrator
Ran 45 tests
OK

# Тесты tools/ в составе bash orchestrator/run.sh --check full
Ran 71 tests
OK
```

Среда текущей проверки: Linux, Python 3.10.12. Тесты выполнения работают с временным
репозиторием; вызовы Codex заменены исполняемой заглушкой. Это проверяет поведение
оркестратора, а не качество генерируемого моделью кода.

Покрыты:

- Сохранённые модели для трёх tier, отключённый по умолчанию push, локальная работа
  без remote и явное включение push.
- Профили проверок `tools`, `orchestrator`, `core`, `data`, `android`, `full`:
  запуск из другого каталога и пути с пробелами, состав гейта перед коммитом,
  остановка при ошибке с сохранением кода возврата, справка и неверные аргументы.
- Вызов `run.sh --check` внутри работающей очереди с повторной попыткой после
  провала проверки; отдельный запуск при занятой блокировке, изменённых файлах,
  некорректной очереди и конфигурации, отсутствующем Codex. Режим проверок не меняет
  ветку, Git-историю, журнал и состояние очереди.
- Вложенный Python-гейт на чистом комплекте не создаёт `__pycache__` в защищённом
  каталоге. Новый регрессионный тест до исправления завершался ошибкой
  «изменены защищённые файлы»; после экспорта `PYTHONDONTWRITEBYTECODE=1`
  проходит. Защита служебных файлов сохранена.
- Полная замена пачки с очисткой очереди и удалением журнала, затем новые задачи
  с повторным использованием ID без архивных файлов.
- Размещение логов в `orchestrator/.runtime/` и отсутствие их в Git-индексе.

- Выполнение нескольких задач в заданном порядке, продолжение, добавление новых задач,
  пропуск завершённых, `--only`, `--from` и отклонение неизвестного ID.
- Успешный gate, повторное исправление новым `exec`, исчерпание попыток,
  остановка без коммита при провале, явный `gate: skip`.
- Ручное завершение с повторным gate, отсутствие вызова Codex в этом режиме.
- Ошибка/пустой ответ/`BLOCKED:` от агента; задача без правок приложения.
- Защита задач, журнала и каталога оркестратора, обнаружение агентского коммита.
- Чистота рабочего дерева, в том числе `orchestrator/`, и запрет автоматического
  перехода на существующую ветку.
- Подлинные Git-коммиты, push в локальный bare-репозиторий, остановка после неудачного push.
- Ошибка commit hook: незакоммиченный журнал не становится молчаливым основанием
  для пропуска задачи при следующем запуске.
- Изменение уже выполненной задачи под прежним ID, пользовательские пути с пробелами,
  модели и effort, префикс команды проверки, linked worktree.
- Межпроцессная блокировка; таймауты Codex и gate; SIGTERM и остановка дочерних процессов.
- Некорректные задачи/конфигурация/пути, дубли ID и полей, русский текст и эмодзи,
  CRLF, заголовки внутри prompt, отсутствие побочных записей у list/dry-run.

Дополнительно выполнены:

- `bash -n orchestrator/run.sh`, `git diff --check` — успешно.
- `bash orchestrator/run.sh --help` и `bash orchestrator/run.sh --check --help` —
  успешно; общая справка описывает очередь и режим проверок.
- `bash orchestrator/run.sh --dry-run` — успешно, рабочая очередь пуста,
  демонстрационные задания в неё не включены. Codex и Git-записи не запускаются.
- Разбор очереди и единственного примера — 0 и 1 задача соответственно; компиляция всех
  Python-файлов оркестратора через `compile()` — успешно.
- Полный гейт `bash orchestrator/run.sh --check full` с локальным JDK 21: обе Python-серии
  прошли, Gradle остановился до выполнения задач с `SDK location not found`.
  `local.properties` указывает на отсутствующий
  `/tmp/words-combination-tools/android-sdk`. Сборка debug не проверена.
- Отдельный `bash orchestrator/run.sh --check core` с тем же JDK 21 — `BUILD SUCCESSFUL`,
  задача `:core:test` получила `UP-TO-DATE` (использован ранее сохранённый результат).
  Для этих запусков `JAVA_HOME` задан на существующий локальный JDK в
  `/tmp/personal-finance-build-tools/jdk-root/usr/lib/jvm/java-21-openjdk-amd64`;
  настройки проекта и системный JDK не менялись. В предыдущей проверке без
  `JAVA_HOME` команда `core` завершилась ошибкой поиска toolchain 21.

Исходные 34 теста комплекта сохранены. Ожидание push изменено по существу:
проект теперь требует явного включения отправки; сценарии push в локальный
bare-репозиторий и обработки ошибок по-прежнему проверяются.

## Не проверялось

- Выполнение заданий настоящими моделями: авторизация, доступность конкретных моделей,
  расход токенов и качество результата зависят от окружения пользователя.
- Android-компиляция, lint и запуск на устройстве: отсутствует настроенный SDK.
  Release не запускался: сборочные файлы не менялись, ручной аудит определений
  остаётся обязательным условием по `AGENTS.md`.
- Удалённый push по SSH/HTTPS; проверен только локальный Git remote.
- Docker: проект использует команды на хосте, `gate_base=[]`.
- macOS и WSL; текущая проверка выполнена на Linux с Python 3.10.

Для первого реального запуска добавьте согласованную задачу в `TASKS.md`,
сохраните изменения коммитом и используйте `--only ID`. Единственный образец
хранится в `examples/TASKS.md`, автоматически не запускается.
