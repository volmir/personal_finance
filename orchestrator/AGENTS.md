# AGENTS.md — правила работы над оркестратором

Этот файл — для правок самого модуля `orchestrator/` (код, тесты,
документация). Правила целевого проекта задаёт корневой `AGENTS.md` того
репозитория, куда модуль установлен; пользовательскую документацию модуля
читайте в `orchestrator/README.md`.

Модуль: последовательное выполнение очереди задач CLI-агентом
(Codex CLI или OpenCode) с обязательным gate, автокоммитом и журналом.
Один каталог, без внешних Python-пакетов, без сети.

## 1. Карта модуля

```
orchestrator.py   вся логика очереди: парсер задач, конфиг, бэкенды,
                  gate, Git, журнал, контрольные точки
checks.py         резолвер профилей --check (встроенный orchestrator
                  + ключ checks из config.json); вызывается run.sh
run.sh            точка входа: очередь (--exec-режим) и режим --check
config.json       настройки экземпляра модуля в конкретном проекте
TASKS.md          рабочая очередь; PROGRESS.md — журнал
tests/            unittest: интеграционные тесты с временными
                  Git-репозиториями и заглушками агентов
examples/         образцы задач и конфига; в очередь не входят
docs/, VALIDATION.md, README.md — план/история, прогоны, инструкция
```

Где что менять: правило игры очереди (парсер, бэкенд, gate, Git, журнал) →
`orchestrator.py` плюс тест; профиль `--check` → `checks.py` или ключ
`checks` конфига; документация → `README.md`/`examples/`; правки
экземпляра (модели, таймауты, профили проекта) → `config.json`, без правок
кода.

## 2. Жёсткие правила

1. **Тесты прежде кода.** Для изменения поведения сначала падающий тест
   в `orchestrator/tests/`, затем правка. Для бага — сначала минимальный
   падающий тест, потом исправление. Не ослабляйте тест ради зелёного
   результата; изменение ожидания объясняйте по существу.
2. **Без внешних зависимостей.** Только стандартная библиотека Python 3.10+
   и Bash. Новые пакеты, бинарники и сеть в коде модуля запрещены.
3. **Совместимость форматов.** `PROGRESS.md` (строки `orchestrator:v1`)
   и `checkpoint.json` (версия 1) — сохранённые состояния; новые поля
   только с значениями по умолчанию, старые файлы должны читаться.
   Fingerprint задачи не должен зависеть от настроек конфига.
4. **Codex-команда стабильна.** Форма команды `codex exec …` меняется
   только по явной задаче и закрепляется тестом байт-инвариантности.
   Это снимает риск незаметного изменения поведения у действующих
   экземпляров модуля.
5. **Конфиг — единственный источник настроек.** Переменные окружения
   не читаются; приоритет: флаги CLI → config.json → дефолты.
   Неизвестные ключи конфига отклоняются.
6. **Защита служебных файлов.** Задачи, журнал, конфиг, `orchestrator.py`,
   `run.sh`, `checks.py` защищены контрольными суммами. Расширяя список
   защищаемых, не забудьте тест и документацию.
7. **Без блокировок UI и фоновых потоков:** модуль однопоточный; таймауты
   через `subprocess` и группы процессов, не через busy-wait.
8. **Секреты не коммитятся** и не попадают в логи: токены, ключи,
   содержимое `calls.jsonl`-логов агентов в тестах — только временные
   каталоги.
9. **Документация модуля самодостаточна:** `README.md` не ссылается на
   конкретный проект, Gradle/Android/npm и т.п.; команды примеров должны
   работать в любом репозитории.

## 3. Проверки

| Что менял | Что запускать |
|---|---|
| Код/тесты модуля | `bash orchestrator/run.sh --check orchestrator` |
| `run.sh` / `checks.py` | плюс `bash -n orchestrator/run.sh` и `bash orchestrator/run.sh --check --help` |
| Документация/примеры | `python3 -c "…"` разбор примеров задач парсером (см. тесты) — очередь не должна ломаться |
| Перед коммитом | весь `--check orchestrator`; при установке в проект — его полный профиль |

Тесты не зависят от сети, аккаунтов агентов, текущего времени и порядка
выполнения: агенты подменяются заглушками, репозитории — временными.
Не используйте `Thread.sleep`-подобные ожидания без таймаута.

## 4. Соглашения

- Язык пользовательских сообщений и документации модуля — русский;
  идентификаторы, ключи конфига и сообщения коммитов — английские.
- Ошибки — класс `Error`/`RetryableError` из `orchestrator.py`; коды
  завершения: 0/1/2/130 — не вводите новых без необходимости.
- Новые флаги CLI: короткие, взаимоисключающие группы документируются
  в `--help` и `README.md`.
- Примеры в `examples/` обновляйте вместе с изменением формата задач
  или конфига.

## 5. Отчёт

Изменённые файлы и что сделано; команды проверок и результат; что не
проверено и почему; риски и смежные находки (не более 5 строк). Один
логический коммит — одно изменение.
